117. ## Technology Stack
118. 
119. | Layer | Technology | Justification |
120. |-------|-----------|---------------|
121. | Input capture | `evdev` (python-evdev) | Direct kernel-level input with exclusive grab support; lowest latency path to controller events on Linux |
122. | HID encoding | `struct.pack` | Zero-dependency binary packing; report descriptor is a static byte array compiled from USB HID spec |
123. | Bluetooth | BlueZ via `bluetoothctl`/`hciconfig` CLI + raw `AF_BLUETOOTH` sockets | BlueZ is the only BT stack on SteamOS; CLI tools avoid heavy D-Bus library dependencies |
124. | L2CAP transport | `socket.AF_BLUETOOTH`, `SOCK_SEQPACKET`, `BTPROTO_L2CAP` | Python stdlib; reliable sequenced packets on PSM 17 (control) and PSM 19 (interrupt) |
125. | Frontend framework | React 18 + TypeScript | Required by DeckyLoader's `@decky/ui` component library |
126. | Build system | Rollup + pnpm (frontend), direct Python execution (backend) | DeckyLoader convention; no Python build step needed since DeckyLoader runs `.py` files directly |
127. 
128. ## BlueZ Integration
129. 
130. The plugin interacts with BlueZ through multiple interfaces:
131. 
132. 1. **`bluetoothd` process management** — stopped via `systemctl stop bluetooth`, restarted with `/usr/lib/bluetooth/bluetoothd -P input --nodetach` to disable the built-in input plugin that would conflict with HID device emulation.
133. 
134. 2. **Adapter configuration** — `bluetoothctl` commands set the adapter alias, discoverable mode, pairable mode, and discoverable timeout. `hciconfig` sets the Bluetooth device class to `0x002508` (gamepad).
135. 
136. 3. **SDP service record** — `assets/gamepad_sdp.xml` defines the HID service with L2CAP PSM 17 (control) and PSM 19 (interrupt), device subclass gamepad, and HID parser version 1.1.1. Registered via `sdptool`.
137. 
138. 4. **Pairing agent** — registered as `NoInputNoOutput` capability via `bluetoothctl agent` for PIN-less pairing.
139. 
140. 5. **L2CAP sockets** — raw Python sockets (`AF_BLUETOOTH`, `SOCK_SEQPACKET`, `BTPROTO_L2CAP`) bound to `BDADDR_ANY` on PSM 17 and 19. Connections are accepted asynchronously via `asyncio.loop.sock_accept()`.
141. 
142. ## Threading Model
143. 
144. The plugin uses Python's `asyncio` event loop (provided by DeckyLoader) as the primary concurrency mechanism:
145. 
146. - **RPC handlers** — `async def` coroutines called by DeckyLoader when the frontend invokes `callable()`
147. - **Connection accept loop** — `asyncio.Task` running `_accept_connections()` that awaits L2CAP socket accepts
148. - **Input read loop** — `asyncio.Task` running `_read_loop()` that uses `evdev.async_read_loop()` for non-blocking event reads
149. - **Config persistence** — `threading.Lock` protects the `Config._data` dict since config can be read from the async context and written from any thread
150. 
151. No additional OS threads are spawned. The `evdev` async reader and socket operations all run on the single asyncio event loop.
152. 
153. ## State Machine
154. 
155. ```mermaid
156. stateDiagram-v2
157.     [*] --> Idle : Plugin loaded
158.     Idle --> Broadcasting : start_broadcasting()
159.     Broadcasting --> Connected : L2CAP accept on PSM 17 + 19
160.     Connected --> Broadcasting : Device disconnects
161.     Broadcasting --> Idle : stop_broadcasting()
162.     Connected --> Idle : stop_broadcasting()
163.     Idle --> [*] : Plugin unloaded
164. ```
165. 
166. | State | `_running` | `_connected_device` | Behavior |
167. |-------|-----------|---------------------|----------|
168. | Idle | `False` | `None` | Normal Steam Deck operation; bluetoothd running in default config |
169. | Broadcasting | `True` | `None` | bluetoothd restarted with `-P input`; adapter discoverable; L2CAP listening; evdev grabbed |
170. | Connected | `True` | `ConnectionInfo(...)` | HID reports sent on every input state change; adapter remains discoverable |
171. 
172. ## Security Model
173. 
174. - **Root privileges** — the plugin runs with root access (set via `"flags": ["root"]` in `plugin.json`). Required for `EVIOCGRAB`, `hciconfig`, `systemctl`, and binding L2CAP sockets on privileged PSM ports (<1024).
175. - **EVIOCGRAB** — the controller device is grabbed exclusively to prevent input events from reaching Steam while broadcasting. Released on stop.
176. - **Bluetooth pairing** — uses `NoInputNoOutput` agent capability (no PIN exchange). This prioritizes ease of use over pairing security. The BT device class and SDP record identify the device as a gamepad, reducing social engineering risk.
177. - **No network access** — the plugin does not make any HTTP/internet requests. All communication is local Bluetooth.
178. 
179. ## Future Considerations
180. 
181. - **Rust HID daemon** — replacing the Python input→HID→L2CAP path with a Rust binary could reduce latency by eliminating GIL contention and Python's asyncio overhead. The Rust daemon would read evdev, pack reports, and write to L2CAP sockets in a single tight loop.
182. - **BLE HID** — Bluetooth Low Energy HID over GATT would enable connections to more devices without Classic BT pairing, but iOS GameController framework support for BLE HID gamepads is limited.
183. - **Multi-connection** — supporting multiple simultaneous connections would require multiplexing HID reports across separate L2CAP socket pairs, plus managing multiple accept loops.

36.

40. 
41. Create a virtual HID device via `/dev/uhid` and let the kernel handle Bluetooth HID hosting.
42.

44. - **Cons**: UHID is designed for creating *local* HID devices (e.g., virtual keyboards), not for *remote* Bluetooth HID device emulation. There is no established path from UHID to Bluetooth HID device role. Would require a custom kernel module or significant BlueZ patching.

47. 
48. Use BLE's HID over GATT profile instead of Classic Bluetooth HID.
49. 
50. - **Pros**: lower power consumption; potentially simpler pairing

52.

54.
